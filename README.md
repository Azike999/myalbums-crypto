# My Albums — шифрование

[English](README.en.md)

My Albums — хранилище фото и видео в Телеграме (@MyAlbumsBot) и в приложениях для iPhone и Android.
Фото шифруются на телефоне **до** отправки, и сервер хранит только шифр. Здесь открыт код, который
это делает, — чтобы вы и любой специалист могли проверить это сами, а не верить нам на слово.

Открыто только шифрование. Остальной код приложения и сервера закрыт.

## Что здесь лежит

| Файл | Что это |
|---|---|
| `crypto.js` | Всё шифрование приложения. Точная копия файла, который получает ваш телефон, байт в байт |
| `lib/noble-p256.js` | Арифметика кривой P-256 для подключения устройства по коду — из открытой библиотеки @noble/curves (MIT). `crypto.js` грузит её только с отпечатком SHA-256 (SRI). Как собрана — `lib/BUILD.md` |
| `SPEC.md` | Описание: алгоритмы, где хранится ключ, что шифруется, что сервер видит открыто, ограничения ([English](SPEC.en.md)) |
| `test_vectors.json` | Проверочные примеры: известный ключ и данные → ожидаемый шифр |
| `tests/check_vectors.mjs` | Проверка примеров на самом `crypto.js` (Node.js 20+), включая официальные примеры RFC 9382 (`tests/rfc9382_vectors.json`) |
| `tests/check_vectors.py` | Та же проверка отдельной программой на Python, написанной по `SPEC.md` без `crypto.js` |
| `tests/make_vectors.mjs` | Как получены примеры |
| `verify.py` | Сверка: скачивает `crypto.js` и `lib/noble-p256.js` из приложения и сравнивает с файлами здесь |
| `SECURITY.md` | Куда сообщить о найденной уязвимости |

## Как проверить самому

**1. Тот ли файл получает ваш телефон.** Нужен Python 3.8+, больше ничего:

```
python verify.py
```

Скрипт скачает `https://app.myalbumsbot.com/static/crypto.js` и `…/static/lib/noble-p256.js` и сравнит SHA-256 с
файлами в репозитории, а заодно проверит, что отпечаток библиотеки, записанный в `crypto.js`, — от этого файла.
`SAME` — файлы одинаковые. `--beta` — заодно проверить пробный канал. Файл отдаётся без изменений
(не сжимается и не «минифицируется»). Сжатие при передаче скрипт отключает и сравнивает ровно те байты,
что исполняет браузер. В приложении файл подключается как `crypto.js?v=<число>` — это только метка для сброса
кэша, содержимое то же.

То же самое можно сделать без скрипта: откройте приложение в Telegram Web в Chrome,
F12 → Sources → `static/crypto.js` и сравните с файлом здесь.

**2. Делает ли код то, что написано в SPEC.md.**

```
node tests/check_vectors.mjs        # примеры на самом crypto.js
pip install cryptography
python tests/check_vectors.py       # независимая проверка по SPEC.md
```

Обе проверки должны закончиться словами `all … checks passed`. Python-проверка не использует `crypto.js`:
если она сходится с примерами, значит формат в `SPEC.md` описан верно (AES-256-GCM, кусочный формат PBC1,
PBKDF2, ECDH P-256 + HKDF, SPAKE2 и остальное). Для SPAKE2 она считает кривую P-256 своей арифметикой
и сверяется с официальными примерами RFC 9382.

**3. Чего этот репозиторий НЕ доказывает** — прочитайте раздел «Ограничения» в `SPEC.md`. Коротко:
страница приложения приходит с нашего сервера, и проверка одного `crypto.js` не исключает, что другой код
страницы отправит ключ куда не надо. Мы честно описываем, чем это закрыто сейчас и чем можно закрыть.
